# Manny 프레임 보정(팔 체인 롤 보정)과 입력 클램프

브랜치 `feature/manny-frame-refinement`의 변경 설명입니다. 모델 재학습 없이, Manny 동작을 모델에 넣기 전의 **스켈레톤 변환 오차**를 바로잡아 전환 품질을 높였습니다.

## 요약

- 전환이 어색했던 가장 큰 원인은 모델이 아니라 **Manny→LAFAN 보정 행렬의 팔 비틀림(롤) 오차**였습니다. 팔꿈치가 LAFAN에 없는 축으로 꺾여 들어가면서, 입력 z-score가 최대 45까지 튀었고 루트·다리 예측까지 망가뜨렸습니다.
- 팔 체인 4개 관절의 롤 값을 실제 Manny 동작에서 추정해 보정하고(`B' = B · Rx(roll)`), 분포 밖으로 크게 벗어나는 쇄골·팔 입력은 z ±3으로 묶었습니다.
- 같은 클립 안 구간을 지우고 다시 채우는 테스트에서 모델 오차가 **단순 보간 대비 0.99배 → 0.52배**, 추정에 쓰지 않은 Quinn 클립에서는 **0.97배 → 0.48배**로 줄었습니다.

## 1. 증상과 원인

| 관찰 | 수치 |
| --- | --- |
| Run 입력 팔꿈치(ForeArm) 채널 z-score | 최대 45 (LAFAN 해당 채널 std 0.014) |
| Run 입력 쇄골(Shoulder) 채널 z-score | 최대 29 (LAFAN 쇄골은 거의 고정, std 0.012) |
| Run 클립 자기 복원 오차 (기존) | 단순 보간의 **1.25배** — 모델이 보간보다 나쁨 |
| Walk→Run(N=20) 경계 루트 보정량 (기존) | 11.5 cm — 모델 궤적이 목표와 어긋나 후처리가 루트를 끌어당김 |

z-score가 큰 입력 몇 채널이 인코더에서 프레임 토큰 전체를 오염시켜, 팔뿐 아니라 루트와 다리 예측까지 틀어졌습니다. 이 채널들만 ±3으로 잘라도 Run 복원 오차가 절반 이하로 줄어드는 것으로 확인했습니다.

팔꿈치 z는 팔을 많이 굽히는 Run·Jump에서만 크게 튀고, 팔을 편 Idle에서는 작았습니다. 이는 **보정 축이 뼈 축을 중심으로 틀어져 있을 때** 나타나는 패턴입니다. 실제로 Manny 애니메이션에서 팔꿈치가 굽는 축을 측정하니, LAFAN 힌지축(로컬 +Z)에서 24~30° 기울어 있었습니다. 무릎은 9~14° 수준이었습니다.

## 2. 보정 행렬이란

Manny와 LAFAN은 관절 22개를 공유하지만 뼈마다 로컬 좌표축 정의가 다릅니다. 그래서 `manny_lafan_transform.apply_global_rest_correction`이 관절마다 고정 3×3 회전 `B`를 곱해 Manny 회전을 LAFAN식 회전으로 바꿉니다. 값은 `Tools/MannyLafanMapping/rest_pose_corrections_22_prototype.json`에 있습니다.

회전의 자유도 3은 **뼈 방향(2) + 뼈 축 둘레 롤(1)**입니다. 현재 값은 Manny `MM_Idle` 0번 프레임과 LAFAN `walk2_subject4` 454번 프레임을 같은 자세로 가정해 역산했습니다. 팔을 편 자세에서는 30° 비틀려도 겉모양이 거의 같기 때문에, 포즈 한 쌍으로는 롤을 정할 수 없습니다. 롤은 관절이 **굽는 방향**으로만 드러납니다.

## 3. 변경 내용

### 3.1 롤 추정 — `Tools/MotionInference/estimate_frame_refinement.py`

1. 플러그인으로 내보낸 Manny 동작(정규화하지 않은 `model_input.json`)에서 팔꿈치 로컬 회전을 모읍니다.
2. 기준 프레임 대비 상대 회전의 회전축을 PCA로 구해, 위팔 프레임과 아래팔 프레임에서의 굽힘 축을 얻습니다.
3. 그 축의 Y 성분이 0이 되도록 각 프레임을 뼈 축(+X) 둘레로 돌리는 롤을 계산합니다.

Manny 클립 7개(MM_*)에서 추정한 결과는 `configs/manny_frame_refinement_v1.json`에 있습니다.

| 관절 | 롤 | 보정 전 굽힘 축 | 보정 후 |
| --- | --- | --- | --- |
| LeftArm (위팔) | −30.0° | (0.034, 0.500, 0.865) | (0.034, 0, 0.999) |
| LeftForeArm (아래팔) | −29.2° | (0.035, 0.488, 0.872) | (0.035, 0, 0.999) |
| RightArm | +24.2° | (−0.103, −0.408, 0.907) | (−0.103, 0, 0.995) |
| RightForeArm | +26.6° | (−0.155, −0.443, 0.883) | (−0.155, 0, 0.988) |

첫 주성분 분산 비율이 0.996~0.997이라, 팔꿈치는 거의 완벽한 단일 축 힌지입니다. 무릎(`--hinges elbows knees`)도 같은 방법으로 추정해 검증했지만 이득이 없어서 기본값에서는 뺐습니다.

### 3.2 적용 위치 — `Tools/MotionInference/infer.py`

보정 JSON 자체를 바꾸지 않고, 모델 호출 **직전에 적용하고 직후에 되돌립니다**.

```
l'_j = C_parent(j)ᵀ · l_j · C_j        # C_j = Rx(roll_j), 모델 입력 직전
l_j  = C_parent(j) · l'_j · C_jᵀ       # 모델 출력 직후
```

이는 보정 행렬을 `B' = B · C`로 바꿔 다시 내보낸 것과 수학적으로 같습니다. `FrameRefinementTests.test_refinement_equals_reexport_with_refined_calibration`이 이 동일성을 검사합니다. 이렇게 한 이유는 다음과 같습니다.

- 내보내기, 역매핑, C++ 플러그인 코드가 바뀌지 않습니다.
- 이미 내보낸 입력 파일과 데모 샘플을 그대로 쓸 수 있습니다.
- 보정 파일과 입력이 서로 다른 보정 행렬로 만들어진 경우를 해시로 검사할 수 있습니다.

### 3.3 입력 z 클램프

쇄골은 LAFAN에서 거의 움직이지 않아(6D std ≈ 0.012) 보정으로 고칠 수 없습니다. 롤 보정도 팔 프레임의 뼈 방향 기울기(5~7°)까지는 잡지 못합니다. 그래서 쇄골·위팔·아래팔·손 6D 채널의 모델 입력 z-score를 ±3으로 자릅니다. 문맥·목표 프레임은 결과에서 원본 그대로 복원하므로, 클램프는 모델이 받는 입력에만 영향을 줍니다.

### 3.4 설정 (`model_config.*.json`)

| 키 | 생략 시 (기본) | `null` | 값 |
| --- | --- | --- | --- |
| `frame_refinement` | `configs/manny_frame_refinement_v1.json` 사용 | 롤 보정 끔 | 설정 파일 기준 상대 경로 |
| `input_z_clamp` | 쇄골·팔·손 8관절, ±3 | 클램프 끔 | `{"limit": 3.0, "joints": [...]}` |

두 키를 모두 `null`로 두면 이전 어댑터와 **비트 단위로 같은 결과**가 나옵니다(N=5·20·45에서 확인). 기존 결과를 재현할 때 사용합니다.

### 3.5 안전장치와 기록

- 보정 파일에 기록된 보정 행렬 해시가 현재 `rest_pose_corrections_22_prototype.json`과 다르면 실행을 거부합니다. 보정 행렬을 바꾸면 롤을 다시 추정해야 합니다.
- 입력의 `mapping_source_sha256`에 다른 보정 행렬 해시가 있으면 실행을 거부합니다.
- Git의 `core.autocrlf` 설정에 따라 보정 행렬 JSON이 LF 또는 CRLF로 체크아웃되므로, 해시는 두 줄바꿈 형태와 모두 비교합니다. 보정 파일에는 LF 기준 해시를 기록합니다.
- 출력 `inference.frame_refinement`에 보정 파일 경로·해시·롤 값을, `inference.input_z_clamp`와 `diagnostics.input_z_clamp`에 클램프 설정과 실제로 잘린 값 개수, 클램프 전 최대 z를 남깁니다.

### 4.2 자기 복원 테스트 (정답이 있는 비교)

같은 클립에서 문맥 10프레임과 N프레임 뒤 목표를 주고, 사이 N프레임을 다시 채운 뒤 원본과 비교합니다. N은 10·15·20이며, LaFAN1 벤치마크와 같은 방식입니다. 기준은 단순 보간(루트 선형 + 로컬 SLERP)입니다.

| 그룹 (구간 수) | 보간 위치 오차 | 기존 | 개선 | 기존 → 개선 (보간 대비) |
| --- | --- | --- | --- | --- |
| 전체 클립 (230) | 7.27 cm | 7.18 cm | **3.79 cm** | 0.99 → **0.52** |
| Quinn MF_* — 추정에 미사용 (81) | 10.19 cm | 9.93 cm | **4.88 cm** | 0.97 → **0.48** |
| Walk·Run (135) | 11.81 cm | 11.33 cm | **5.54 cm** | 0.96 → **0.47** |
| Run만 (54) | 18.25 cm | 22.74 cm | **8.75 cm** | 1.25 → **0.48** |
| Jump·Land·Fall (41) | 1.79 cm | 2.75 cm | 2.55 cm | 1.54 → 1.42 |
| Idle (54) | 0.07 cm | 0.18 cm | 0.35 cm | 모두 1 cm 미만 |

Walk·Run에서 루트 오차는 8.9 → 3.9 cm, 팔 회전 오차는 13.1° → 8.6°, 다리 회전 오차는 14.7° → 11.4°로 줄었습니다. LaFAN1 테스트셋에서 공식 모델의 보간 대비 비율이 0.28~0.39이므로, 개선 후의 0.47~0.52는 그 범위에 가까워졌습니다.

| 클립 | 왼팔 보정 전 → 후 | 오른팔 보정 전 → 후 |

| MM_Run_Fwd | 45.2 → 5.2 | 39.5 → 11.4 |

팔을 거의 펴는 Idle은 약간 올라가는데, 롤로 잡지 못한 뼈 방향 기울기 때문입니다. 클램프가 이를 ±3으로 막습니다.

### 4.4 전환 비교 (플러그인 기본 요청, N=20)

시작 클립 첫 31샘플의 마지막 10프레임을 문맥으로, 목적지 0번 프레임을 목표로 썼습니다. 정답이 없으므로 그럴듯함 지표로 비교합니다. 원본 클립의 발 미끄러짐은 약 1 cm/프레임입니다.

| 전환 | 경계 루트 보정 (기존 → 개선) | 발 미끄러짐 cm/프레임 | 최저 발끝 높이 |
| --- | --- | --- | --- |
| WalkToRun | 11.5 → **2.8** cm | 3.7 → **2.4** | −3.0 → −2.8 cm |
| RunToWalk | 8.8 → **1.3** | 10.5 → **6.4** | −4.1 → −6.7 |
| RunToIdle | 4.8 → **0.7** | 10.1 → **4.4** | −2.2 → −4.6 |
| RunToJump | 18.8 → **2.3** | 10.7 → **3.3** | −4.1 → −2.5 |

경계 루트 보정량은 모델 궤적과 배치된 목표가 얼마나 어긋났는지를 뜻하고, 클수록 후처리가 루트를 끌어당겨 발이 미끄러집니다.

## 6. 한계와 다음 단계

- **Jump·Land·Fall**: 개선 후에도 모델이 단순 보간보다 나쁩니다(1.42배). LAFAN에 없는 Manny 키프레임 동작의 한계로 보입니다.
- **지면 관통**: 발이 덜 미끄러지는 대신 일부 전환에서 발끝이 지면 아래로 최대 6.7 cm 들어갑니다. 발 IK 후처리(접촉 검출 → 발 고정 → 2본 IK)가 필요합니다.
- **전환 길이**: 공식 모델은 5~30프레임으로 학습됐습니다. 31~45는 외삽 구간이라 끝부분에서 감속 후 튀는 현상이 남습니다.
- **위상 선택**: 시작·목표 프레임 조합에 따라 발 미끄러짐이 최대 7배 달라집니다. 후보를 일괄 추론해 고르는 기능이 다음 과제입니다.
- **나머지 본**: 손가락·twist·IK 본은 아직 reference pose로 저장되어 경계에서 손 모양이 바뀔 수 있습니다.
- **뼈 방향**: 팔 프레임의 5~7° 방향 기울기는 롤 보정에 포함하지 않았습니다(클램프로 완화).

## 7. 재현 방법

`Tools/MotionInference/batch/README.md`를 따르면 클립 내보내기 → 롤 재추정 → 자기 복원 평가 → 비교 전환 생성 → UE 에셋 생성을 다시 실행할 수 있습니다. 클립을 더 추가했다면 롤을 다시 추정해 `configs/manny_frame_refinement_v1.json`을 갱신하고, 새 기본값 기준선(`Tests/Fixtures/refined_context_detail_baseline.*`)도 다시 만들어야 합니다.
